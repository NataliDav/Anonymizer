# Техническое задание
## «Локальный анонимизатор таблиц» (Local Table Anonymizer)

**Версия:** 1.0
**Дата:** 24.08.2026

---

## 1. Общие сведения

### 1.1. Наименование
Программное средство «Локальный анонимизатор таблиц» (далее — Приложение).

### 1.2. Назначение
Приложение предназначено для **локальной псевдонимизации персональных данных** в электронных таблицах: замены персональных данных (ФИО, адрес, телефон и т. п.) на обезличенные индексы с возможностью последующего **обратного восстановления** исходных значений по файлу-ключу.

### 1.3. Ключевые принципы
| Принцип | Требование |
|---|---|
| Изоляция от сети | Приложение **не выполняет ни одного сетевого запроса**: ни во время установки зависимостей после первого развёртывания, ни во время работы. |
| Без нейросетей | Вся обработка выполняется **детерминированными алгоритмами** (нумерация, хеширование HMAC-SHA256, шифрование). Никаких ML/AI-компонентов, никаких внешних API. |
| Локальность | Работает только на компьютере пользователя. Данные не покидают файловую систему. |
| Обратимость | Исходные данные можно восстановить, загрузив изменённую таблицу + файл-ключ обратно в приложение. |

---

## 2. Цели и задачи

**Цель:** обеспечить безопасную работу с таблицами, содержащими персональные данные (ПДн): пользователь передаёт/обрабатывает обезличенную копию, а оригинальные значения хранятся отдельно в зашифрованном файле-ключе на его же компьютере.

**Задачи:**
1. Реализовать загрузку таблиц в форматах `.xlsx` и `.csv`.
2. Реализовать выбор столбцов с ПДн для анонимизации.
3. Заменить каждое уникальное значение ПДн стабильным индексом (`ПЕРСОНА_0001`, `ADDR_0001`, `PHONE_0001`).
4. Сохранить словарь соответствий «индекс ↔ исходное значение» в зашифрованном файле-ключе.
5. Выгрузить анонимную таблицу в `.xlsx` / `.csv`.
6. Реализовать обратный режим: загрузка анонимной таблицы + файла-ключа → восстановление исходной таблицы.
7. Предоставить простой графический интерфейс (GUI), опционально — режим командной строки (CLI).

---

## 3. Термины и определения

- **ПДн** — персональные данные (ФИО, адрес, телефон, e-mail и т. п.).
- **Анонимизация (псевдонимизация)** — замена значений ПДн на индексы-заменители.
- **Файл-ключ (keyfile)** — зашифрованный JSON-файл со словарём соответствий и метаданными; единственный способ восстановить данные.
- **Соль (salt)** — случайная строка, включаемая в вычисление отпечатка значения для защиты от атак по радужным таблицам.
- **Fingerprint** — короткий HMAC-SHA256-отпечаток исходного значения; хранится в файле-ключе для контроля целостности при обратной операции.

---

## 4. Описание входных данных

Эталонный пример — файл `Data_unput.xlsx` (21 запись):

| № | ФИО | Адрес | Телефон | Количество продаж | Аванс (руб.) | Отработано дней | Премия (руб.) | Часы в интернете |
|---|-----|-------|---------|---|---|---|---|---|---|
| 1 | Иван Царевич | Тридевятое царство, дворец царя Берендея | +7 (999) 001‑11‑22 | 15 | 5000 | 12 | 3000 | 8 |

Столбцы делятся на:
- **Столбцы ПДн** (подлежат замене): `ФИО`, `Адрес`, `Телефон`;
- **Бизнес-столбцы** (не изменяются): `Количество продаж`, `Аванс (руб.)`, `Отработано дней`, `Премия (руб.)`, `Часы в интернете`;
- **Служебный столбец** `№` — не изменяется (кроме случая, когда пользователь сам включит его в обработку).

Требование: состав столбцов **не должен быть жёстко зашит** — пользователь выбирает столбцы для анонимизации вручную на любом наборе данных.

## 5. Функциональные требования

### 5.1. Режим «Анонимизация»

| ID | Требование |
|----|-----------|
| F1.1 | Загрузка файла `.xlsx` или `.csv` (разделитель `,`; автоопределение кодировки UTF-8 / cp1251; разделитель `;` — опция). |
| F1.2 | Отображение таблицы (первые строки) и списка всех столбцов с чекбоксами. |
| F1.3 | Пользователь отмечает столбцы ПДн. Для каждого выбранного столбца автоматически предлагается префикс индекса (по имени столбца: `FIO_`, `ADR_`, `TEL_`); префикс редактируемый. |
| F1.4 | Задание пароля для шифрования файла-ключа (минимум 8 символов, подтверждение). Пароль никуда не сохраняется и не записывается на диск в открытом виде. |
| F1.5 | Генерация анонимной копии таблицы (см. алгоритм §6). |
| F1.6 | Сохранение: `<имя>_anon.xlsx` (или `_anon.csv`) и `<имя>_KEY.kvault` (файл-ключ) рядом с исходным файлом либо по выбору пользователя. |
| F1.7 | Итоговый отчёт: сколько уникальных значений заменено в каждом столбце, путь к созданным файлам. |
| F1.8 | Пустые ячейки остаются пустыми (индекс не назначается), факт пропусков фиксируется в отчёте. |

### 5.2. Режим «Восстановление»

| ID | Требование |
|----|-----------|
| F2.1 | Загрузка анонимной таблицы (`.xlsx`/`.csv`) и файла-ключа `.kvault`. |
| F2.2 | Запрос пароля файла-ключа. Неверный пароль → понятное сообщение об ошибке, без частичного восстановления. |
| F2.3 | Сопоставление: если в ячейке стоит индекс, известный файлу-ключу, он заменяется исходным значением. |
| F2.4 | Контроль целостности: HMAC-отпечаток каждого восстановленного значения сверяется; при расхождении — предупреждение с указанием ячейки (файл-ключ мог быть подделан). |
| F2.5 | Ячейки с неизвестными индексами помечаются маркером `[?? НЕИЗВЕСТНО]` и перечисляются в отчёте (не молча игнорируются). |
| F2.6 | Сохранение восстановленной таблицы как `<имя>_restored.xlsx`. |

### 5.3. Общие требования

| ID | Требование |
|----|-----------|
| F3.1 | Все операции логируются в локальный файл `anonymizer.log` (без записи содержимого ячеек в лог — только факты операций). |
| F3.2 | Поддержка повторного запуска анонимизации на том же файле: тот же файл-ключ + та же соль → те же индексы (детерминированность). Новая сессия без ключа → новые индексы. |
| F3.3 | Одинаковым значениям в столбце всегда соответствует один индекс («Иван Царевич», встречающийся 3 раза, получит один `FIO_0001`). Это требование к алгоритму. |
| F3.4 | Опциональный CLI: `python anonymizer.py encode in.xlsx --cols "ФИО,Адрес,Телефон" --out out.xlsx`; `python anonymizer.py decode anon.xlsx --key key.kvault`. |

## 6. Алгоритм обработки (без нейросетей)

### 6.1. Анонимизация
Для каждого выбранного столбца C и каждой непустой ячейки v:

```
1. salt_C = случайные 16 байт (генерируются один раз за сессию для столбца C,
   сохраняются в файл-ключ)
2. fingerprint = HMAC-SHA256(key = session_secret, msg = salt_C || normalize(v))[:8]
   где normalize(v) = v.strip().lower()  # чтобы «иван царевич» == «Иван Царевич»
3. Если fingerprint впервые встречается в столбце C:
       counter[C] += 1
       index_map[C][fingerprint] = { index: f"{prefix}_{counter:04d}",
                                     value: v }        # оригинал только в keyfile
4. В анонимной таблице ячейка := index_map[C][fingerprint].index
```

- Индекс назначается **по порядку первого появления** (стабильно и человеко-читаемо: `FIO_0001, FIO_0002…`).
- Хеширование нужно только для сопоставления повторов внутри сессии; сами хеши не позволяют восстановить значение (однонаправленная функция + соль).

### 6.2. Файл-ключ (.kvault)
JSON-структура вида:

```json
{
  "format": "kvault-1",
  "created": "2026-08-24T19:30:00",
  "source_file": "Data_unput.xlsx",
  "columns": {
    "ФИО":     {"prefix": "FIO_", "salt_hex": "...", "next_counter": 18},
    "Адрес":   {"prefix": "ADR_", "salt_hex": "...", "next_counter": 18},
    "Телефон": {"prefix": "TEL_", "salt_hex": "...", "next_counter": 18}
  },
  "entries": [
    {"col": "ФИО", "fp": "a1b2c3d4e5f60718",
     "idx": "FIO_0001", "val": "Иван Царевич"},
    ...
  ]
}
```

Шифрование файла: библиотека `cryptography` (уже установлена в системе), схема **Fernet (AES-128-CBC + HMAC-SHA256)**. Ключ шифрования выводится из пароля функцией **PBKDF2-HMAC-SHA256** (600 000 итераций, случайная соль 16 байт, хранится в заголовке файла). Целостность обеспечивается встроенным токеном Fernet.

### 6.3. Восстановление
```
для каждой ячейки анонимной таблицы в столбцах из keyfile:
    idx = значение ячейки
    если idx найден в reverse_index[col]:  ячейка := entries[idx].val
    иначе:                                  ячейка := "[?? НЕИЗВЕСТНО]"  (+ запись в отчёт)
```

Модульная структура, слои не смешиваются:


## 8. Интерфейс пользователя (GUI)

Один общий фрейм с двумя вкладками.

### 8.1. Вкладка «Анонимизация»
1. Поле выбора входного файла (кнопка «Обзор…») + превью первых 10 строк.
2. Таблица столбцов: имя / чекбокс «Анонимизировать» / поле префикса.
3. Поле пароля + подтверждение; индикатор надёжности (длина ≥ 8).
4. Кнопки: «Выполнить анонимизацию», «Сохранить как…».
5. Панель результата: статистика по столбцам, пути к `_anon.*` и `_KEY.kvault`.

### 8.2. Вкладка «Восстановление»
1. Выбор анонимной таблицы + выбор файла-ключа.
2. Поле пароля.
3. Кнопка «Восстановить»; превью результата; сохранение `_restored.xlsx`.
4. Журнал предупреждений (неизвестные индексы, ошибки целостности).

Все сообщения об ошибках — человеческим языком, в диалоговых окнах; исключения не должны «ронять» окно приложения.

## 10. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Файл не .xlsx/.csv или повреждён | Сообщение «Не удалось прочитать файл», детали в лог |
| Пустая таблица / нет столбцов | Предупреждение, отказ операции |
| Не выбран ни один столбец ПДн | Диалог «Отметьте хотя бы один столбец» |
| Пароль < 8 символов / не совпадает подтверждение | Диалог валидации |
| Неверный пароль к .kvault | «Неверный пароль или повреждённый файл-ключ», операция отменена целиком |
| Файл-ключ от другой таблицы (столбцы не совпадают) | Предупреждение с перечнем несовпадающих столбцов, предложение продолжить/отменить |
| Запись в защищённую папку запрещена | Предложение выбрать другое место сохранения |

## 12. Сценарии приёмки

1. **Полный цикл на эталоне.** Загрузить `Data_unput.xlsx` → отметить `ФИО, Адрес, Телефон` → анонимизировать. В `_anon.xlsx`: вместо «Иван Царевич» — `FIO_0001`, телефон `+7 (999) 001‑11‑22` → `TEL_0001`; числовые столбцы байт-в-байт не изменились.
2. **Повторяемость.** Повторная анонимизация того же файла тем же ключом даёт идентичные индексы.
3. **Восстановление.** `_anon.xlsx + KEY.kvault + верный пароль` → `_restored.xlsx` полностью совпадает с исходником (автотест сравнивает все ячейки).
4. **Отказоустойчивость.** Неверный пароль → отказ без частичных файлов; подмена одной буквы в `_anon.xlsx` → предупреждение о неизвестном индексе, остальные строки восстановлены.
5. **Изоляция.** Тест grep'ом подтверждает отсутствие сетевых импортов; приложение работает при отключённом Wi-Fi.
6. **Другие данные.** Анонимизация произвольного csv с другими именами столбцов проходит без правок кода.

## 13. Ограничения и риски

| Риск | Митигация |
|---|---|
| Утеря файла-ключа и/или пароля = невозвратная потеря данных | Явное предупреждение в GUI; рекомендация хранить копию `.kvault` на отдельном носителе |
| Перебор пароля по `.kvault` | PBKDF2 600k итераций; требование к длине пароля; предупреждение об ответственности |
| Косвенная деанонимизация через редкие бизнес-значения (например, уникальный адрес + единственные продажи) | Вне рамок версии 1.0; упомянуть в справке (k-анонимность — кандидат в версию 2.0) |
| Очень большие файлы (> 500 МБ xlsx) | Ограничить поддержку: предупреждение, рекомендация CSV |
